updated: 2026-10-16T11:48

- (direction) dillera: port the Palm/HotSync work from classic fujinet-firmware (branch palm-demo-fozz) into NIO as a clean re-implementation to NIO standards, not a copy.
- (decision) Phase 0 output is a design proposal (backlog file + this spec) for Mark to agree before code; classic PR #1826 stalled on cradle hook-in design, so agree architecture first.
- (capability) CAP-1 portable HotSync protocol core (SLP, PADP/CMP, NetSync, DLP, PDB/PRC, session) with capture-based host tests.
- (capability) CAP-2 HotSync over Wi-Fi via NetSync TCP 14238: identify user, install queue, backup.
- (capability) CAP-3 Palm apps use NIO through a Palm platform in fujinet-nio-lib (m68k, C89, cradle at 115200).
- (capability) CAP-4 one serial cradle carries both FujiBus app traffic and HotSync sessions via a channel adapter that owns the line.
- (capability) CAP-5 HotSync settings in fujinet.yaml and status in the diagnostics console.
- (capability) CAP-6 one-way calendar to Palm Date Book conduit (ICS first).
- (decision) Palm apps are ported to NIO commands (Network 0xFD etc.) via a fujinet-nio-lib Palm platform; no classic-command compatibility layer on FujiBus, since NIO keeps LegacyNetworkAdapter off FujiBus.
- (decision) Line sharing is a channel adapter beneath the unchanged FujiBusTransport (Atari SIO adapter pattern); HotSync never touches the UART directly.
- (decision) HotSync is a platform service, not a VirtualDevice; it owns a task because a sync blocks for minutes.
- (constraint) No #ifdef in core/device/transport/config; gnu++17 for shared code (ESP32); constructor injection only; no globals.
- (constraint) Database buffers capped and in PSRAM on ESP32 (review feedback on #1826).
- (constraint) Code derived from palm-sync carries its Apache-2.0 notice; no pilot-link (GPL) code.
- (question) NIO has no long-lived service task abstraction (large_stack waits for completion). Add one, or write the session as a poll-driven state machine?
- (question) Is an explicit 'sync now' FujiBus command wanted to shorten or replace the 9600-baud listening windows?
- (question) Which wire ID / service owns Palm install-queue and HotSync status commands, if any are exposed on FujiBus?
- (question) Does Google Calendar/OAuth have a planned home in NIO, or is ICS over HTTP enough for CAP-6?
- (assumption) CloudpilotEmu via socat pty does not model baud mismatch, so baud-switch behaviour needs real-cradle testing.
- (decision) Companions: brownfield.md (classic-to-NIO map, NIO touchpoints), palm-protocols.md, cradle-sharing.md, failure-modes.md. Stories deferred until maintainer agrees the open questions.
- (event) Self-validate pass 1 (coherence): 6 CAPs each with intent+success; constraints each rule out an option; 6 non-goals; success signal is a hardware demo plus POSIX run. Pass.
- (event) Self-validate pass 2 (preservation): classic inventory (protocol facts, timings, retry policy, Date Book fixes, PR #1824/#1826 review points) landed in companions; classic web UI and Google OAuth deliberately excluded as non-goals.
- (direction) dillera confirmed: Palm apps rebuilt on fujinet-nio-lib (no classic compat layer); Palm client phase runs in parallel with HotSync phases. Open questions go to Mark via Discord and a GitHub issue.
